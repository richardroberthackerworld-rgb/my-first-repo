Tell your students the answer is wrong
before they do.

7Solve checks a maths answer against its own question — with a parser and a substitution engine, not a second language model. It costs nothing per call because nothing is generated.

POST /v1/verify  →  x² + y² + 1 = 3xy  ·  answer: (5,3)
✗(x,y) = (5,3) in x²+y²+1=3xy gives 35 ≠ 45
✓16 − 24 = −8
DISPUTED the answer contradicts the question

A real response. The model that produced (5,3) was confident and wrong; 35 ≠ 45 is not an opinion.

What this is

Every AI tutor sometimes returns a confident wrong answer, and a student revising for an exam cannot tell it from a correct one. This API is the check that sits between the two.

Send a question and a proposed answer. You get back a verdict, plus the arithmetic behind it, so you can show the working or suppress the answer entirely. The answer can come from your model, your content team, or the student — it does not have to come from us.

Base URL

https://7solve.7by.in/v1

Authentication

Every endpoint except /health needs a key in the header.

Authorization: Bearer 7solve_live_a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6

Keys are shown once. We store only a SHA-256 of the key, the same way a password is stored, so a stolen key file is worth nothing on its own — and a key you lose cannot be recovered. Save it when it is issued and rotate it if it leaks.

The four verdicts

Every verification resolves to one of four states. They are not a confidence score, and they are not ranked on a single axis — each one means a different thing about what was tested.

StatusMeansWhat to do
CHECKED Every check that could run agreed with the answer. Show it.
STEPFAIL The answer stands, but a step in the working does not hold. Show it with the caveat. Often a typo in the explanation.
DISPUTED The answer contradicts the question. Do not show it as correct. Re-solve or escalate.
UNVERIFIED Nothing here could be checked mechanically. Treat exactly as you would an unchecked answer.

UNVERIFIED is not a pass. It is the honest result for “explain photosynthesis”, for a question with no equation in it, and for anything the parser declines. If your code maps status != "DISPUTED" to “safe to show”, you have turned a silence into an approval — which is the one way this API can make your product worse rather than better. Check verified === true.

Verify an answer

POST /v1/verify key required

The core endpoint. No model is called, so there is no per-call cost and no upstream to be down.

Request

curl https://7solve.7by.in/v1/verify \
  -H "Authorization: Bearer $SEVENSOLVE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "question": "Find positive integers x,y with x^2+y^2+1=3xy",
    "answer":   "The smallest solution is (5,3)."
  }'
FieldTypeNotes
questionstringRequired. LaTeX is accepted and stripped before parsing.
answerstringRequired. Markdown and LaTeX both fine.

Response

{
  "success": true,
  "api_version": "v1",
  "status": "DISPUTED",
  "verified": false,
  "means": "The answer contradicts the question. Do not show it to a student as correct.",
  "checks_run": 1,
  "checks_passed": 0,
  "checks_failed": 1,
  "checks": [
    {
      "kind": "subst",
      "ok": false,
      "text": "(x,y) = (5,3) in x^2+y^2+1=3xy gives 35 ≠ 45"
    }
  ]
}
FieldNotes
verifiedBoolean. true only for CHECKED. This is the field to branch on.
checks[].kindintegrity, subst, units, domain, exhaust and counter dispute the answer; arith, sequence, step and unitconv dispute a step in the working. unitconv checks a unit conversion or the unit a calculation produces, in magnitude as well as dimension — units asks whether the answer is the right kind of thing, unitconv asks whether the number and the unit follow from the working. counter carries an explicit counterexample to a universal claim and can only ever fail — a clean search is not a proof. step means the working lost a solution between one line and the next. domain means a value satisfies the equation but not the domain the question set (positive, non-negative, distinct, prime, or an ordering between variables). exhaust, descent and pell are the kinds that certify a multi-variable solution set as COMPLETE, and each is emitted only where the region was proved rather than searched — see What it can check. descent and pell are the two that reach an INFINITE solution set: descent runs the Vieta jump itself, proves the box every terminal of the descent lies in, and reports the solution set as the union of their orbits; pell does the same job for x² − Dy² = N using the fundamental unit from the continued fraction of √D, over the range Nagell's bound proves holds a representative of every class. Both can fail as well as certify: a finite list offered as complete for an infinite set is refuted with the solution that breaks it named, and a family covering one branch of several is refuted by naming a branch it never reaches. Both return nothing at all when the region cannot be proved.
checks[].textHuman-readable and safe to show a student verbatim.
checks orderFailures first. A receipt that buries the failure under ten ticks contradicts its own heading.

What it can check

Substituting claimed roots and tuples back into the question’s equation; arithmetic written in the working; exact surd forms such as 82 ± 30√7; fraction equalities; and the dimensions of a physics answer, so “find the acceleration” answered in newtons is caught before any arithmetic is examined. It deliberately declines trigonometric equations, because degrees-or-radians is a convention your question may not share and a wrong verdict is worse than none.

Domain, and what “all solutions” is allowed to mean

A question that says positive integers, non-negative integers, distinct, primes, or x > y has narrowed the domain, and a value satisfying the equation but not the domain is not a solution. That is the domain kind, and it disputes the answer.

A question that says find all is asking for something stronger than a list of solutions that check out. Substitution proves each value genuine; it cannot prove there are no others, and for x² + y² + 1 = 3xy there are infinitely many. So for a multi-variable “find all”, passing substitutions alone return UNVERIFIED, never CHECKED — the receipt still shows that each value was checked.

CHECKED for such a question requires the exhaust kind, which is emitted only where the search region was proved finite rather than assumed. Today that is the family P(x₁…x_k) = c^L with P a polynomial, c ≥ 2 an integer and L a linear form with every coefficient at least 1, over integers bounded below. There, with s = Σxᵢ, M the sum of the absolute values of P’s coefficients and d its degree, every solution has s < S₀ because |P| ≤ M·s^d while c^s > M·s^d for all s ≥ S₀ — proved by induction in exact integer arithmetic, not asserted from “exponentials grow faster” — and the region below S₀ is then enumerated whole. Outside that family the API says nothing about completeness rather than reporting a bounded search as a proof.

Question integrity

One check runs before all the others and asks a different question: is this the problem that was actually set? A model that reads 3x+y as 3(x+y) will produce a flawless solution, pass every other check, and be wrong — because the answer is correct for a problem nobody asked. 

{
  "status": "DISPUTED",
  "checks": [{
    "kind": "integrity",
    "ok": false,
    "text": "the question is 3x+y = 7 but the answer solves 3(x+y) = 7, which is a
             different equation — the answer may be correct for a problem that
             was not asked"
  }]
}

It reads only the restatement at the top of a reply, skips x = 2 style solution lines, and treats a constant multiple as the same relation — so 6x+2y=14 agrees with 3x+y=7. Derived steps are not misreadings and are never flagged as such.

Mark a student's answer

POST /v1/answer/check key required

A different question from /verify, and a different buyer. That endpoint asks whether an AI got it right; this one asks whether a student did — and returns marks, the mistakes, and feedback you can show them.

Deterministic throughout. The true roots come from the solver, the student's come from the same reader the verifier uses, and the mark is set comparison — so it arrives with a proof rather than an opinion, and costs nothing per call. 

curl https://7solve.7by.in/v1/answer/check \
  -H "Authorization: Bearer $SEVENSOLVE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "question":       "Solve x^2 - 4 = 0",
    "student_answer": "x = 2",
    "max_marks":      2
  }'
{
  "success": true,
  "status": "INCOMPLETE",
  "marks": 1,
  "out_of": 2,
  "variable": "x",
  "equation": "x^2 - 4 = 0",
  "expected": [-2, 2],
  "given": [2],
  "mistakes": [
    { "type": "missing_root", "text": "x = -2 is also a solution and was not given" }
  ],
  "feedback": "Every value given is right, but 1 more solution was missed. …",
  "deterministic": true
}
StatusMeans
CORRECTEvery solution given, none wrong.
INCOMPLETEEverything given is right, but a solution was missed.
PARTIALSome values right, some wrong.
INCORRECTNothing given satisfies the equation.
UNMARKABLECould not be marked. marks is null, not zero.

UNMARKABLE is never a zero. A student must not lose marks because the grader could not read the question — a complex root, an unfamiliar phrasing, an equation the solver declines. Route those to a human; marks comes back null so they cannot be summed into a total by accident.

Marking scheme

penalty_per_wrong sets what each wrong value costs, as a fraction of one root's worth. It defaults to 0 — credit for what is right, no deduction — because that is the common school scheme. Set it to 1 for negative marking.

Answer to x² − 4 = 0penalty 0penalty 0.5penalty 1
x = 2 and x = 31 / 20.5 / 20 / 2

Solve, deterministically

POST /v1/math/solve key required

Solves without asking a model anything, so it cannot hallucinate and costs nothing per call. 

curl https://7solve.7by.in/v1/math/solve \
  -H "Authorization: Bearer $SEVENSOLVE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"equation": "x^2 - 164x + 424 = 0"}'
{
  "success": true,
  "status": "SOLVED",
  "kind": "quadratic",
  "variable": "x",
  "roots": [2.627460668, 161.372539332],
  "exact_form": ["82 + 30√7", "82 - 30√7"],
  "discriminant": 25200,
  "method": "exact (quadratic formula)",
  "complete": true
}
StatusMeans
SOLVEDRoots found. Check complete.
IDENTITYTrue for every value of the variable.
NO_SOLUTIONReduces to a false statement.
NO_SOLUTION_FOUNDNothing found in the searched range. Not the same as “none exist”.
UNDEFINEDDivision by zero, or a root of a negative.
UNSUPPORTEDOutside what it can prove it handles. reason says why.

complete: false means the root list may be partial. Linear and quadratic equations are solved exactly and are always complete. Anything else falls to numeric bisection over −1000 to 1000, which misses roots outside that range and repeated roots that never cross zero. The response says so in note rather than leaving you to find out.

It refuses more than one variable, trigonometric equations, and anything the parser declines. A solver that guesses is indistinguishable from one that knows, so this one does not guess.

Solve with a model, then verify

POST /v1/solve key required

Routes the question to a language model, verifies the reply, and — if the verdict is DISPUTED — discards it and tries the next engine. You get the first answer that survives checking, not the first answer produced. 

curl https://7solve.7by.in/v1/solve \
  -H "Authorization: Bearer $SEVENSOLVE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "question": "Solve x^2 + 4x + 6 = 0",
    "class": "10",
    "subject": "mathematics",
    "language": "English",
    "explanation_level": "class_10"
  }'
FieldNotes
questionRequired. Up to 8000 characters.
class, subject, language, explanation_levelOptional. They shape how the answer is written.

The response carries answer, the same verification block as /verify, the engine that produced it, and an attempts array showing every engine tried with its latency and outcome. If every engine returned a disputed answer, status is UNCERTAIN and the best available reply is returned clearly labelled — never silently.

Unlike the two endpoints above, this one calls a model, so it is the one with a real per-call cost and a dependency on upstream availability.

Health

GET /v1/health no key

Safe to poll from a monitor. The engine field reflects a live self-check of the verifier, not just “the process is up”.

{
  "success": true,
  "status": "HEALTHY",
  "engine": "ok",
  "detail": null,
  "store": "writable",
  "time": "2026-08-18T03:55:00+00:00"
}

status is HEALTHY, DEGRADED, or DOWN. A degraded engine returns 200 with a detail string; a down one returns 503.

Managing keys

Key administration uses your admin token, not a customer key.

# issue
curl -X POST https://7solve.7by.in/v1/keys \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"label": "acme-edtech", "rate_per_hour": 600}'

# list (prefixes only — never the key itself)
curl https://7solve.7by.in/v1/keys -H "Authorization: Bearer $ADMIN_TOKEN"

# revoke
curl -X DELETE https://7solve.7by.in/v1/keys/k_9f3c1a2b \
  -H "Authorization: Bearer $ADMIN_TOKEN"

Revoking marks a key dead but keeps its history, so a key id in an old log can still be explained.

Returns this key’s own counters — the current hour against its limit, and totals per day broken down by route.

Errors

Every failure has the same shape, including the ones thrown by the framework itself.

{
  "success": false,
  "api_version": "v1",
  "status": "RATE_LIMITED",
  "message": "This key has used its 600 requests for this hour."
}
StatusHTTPMeans
UNAUTHORIZED401Missing, unrecognised, or revoked key.
NEEDS_CLARIFICATION400A required field is missing or empty.
RATE_LIMITED429Hourly limit reached. Honour Retry-After.
FAILED4xx / 5xxEverything else. message says what went wrong.

Unknown routes return 401 rather than 404 when unauthenticated — route names are not revealed to callers without a key.
