Tell your students the answer is wrong
before they do.

7Solve checks a maths answer against its own question — with a parser and a substitution engine, not a second language model. It costs nothing per call because nothing is generated.

POST /v1/verify  →  x² + y² + 1 = 3xy  ·  answer: (5,3)
✗(x,y) = (5,3) in x²+y²+1=3xy gives 35 ≠ 45
✓16 − 24 = −8
DISPUTED the answer contradicts the question

A real response. The model that produced (5,3) was confident and wrong; 35 ≠ 45 is not an opinion.

What this is

Every AI tutor sometimes returns a confident wrong answer, and a student revising for an exam cannot tell it from a correct one. This API is the check that sits between the two.

Send a question and a proposed answer. You get back a verdict, plus the arithmetic behind it, so you can show the working or suppress the answer entirely. The answer can come from your model, your content team, or the student — it does not have to come from us.

Base URL

https://7solve.7by.in/v1

Authentication

Every endpoint except /health needs a key in the header.

Authorization: Bearer 7solve_live_a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6

Keys are shown once. We store only a SHA-256 of the key, the same way a password is stored, so a stolen key file is worth nothing on its own — and a key you lose cannot be recovered. Save it when it is issued and rotate it if it leaks.

The four verdicts

Every verification resolves to one of four states. They are not a confidence score, and they are not ranked on a single axis — each one means a different thing about what was tested.

StatusMeansWhat to do
CHECKED Every check that could run agreed with the answer. Show it.
STEPFAIL The answer stands, but a step in the working does not hold. Show it with the caveat. Often a typo in the explanation.
DISPUTED The answer contradicts the question. Do not show it as correct. Re-solve or escalate.
UNVERIFIED Nothing here could be checked mechanically. Treat exactly as you would an unchecked answer.

UNVERIFIED is not a pass. It is the honest result for “explain photosynthesis”, for a question with no equation in it, and for anything the parser declines. If your code maps status != "DISPUTED" to “safe to show”, you have turned a silence into an approval — which is the one way this API can make your product worse rather than better. Check verified === true.

Verify an answer

POST /v1/verify key required

The core endpoint. No model is called, so there is no per-call cost and no upstream to be down.

Request

curl https://7solve.7by.in/v1/verify \
  -H "Authorization: Bearer $SEVENSOLVE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "question": "Find positive integers x,y with x^2+y^2+1=3xy",
    "answer":   "The smallest solution is (5,3)."
  }'
FieldTypeNotes
questionstringRequired. LaTeX is accepted and stripped before parsing.
answerstringRequired. Markdown and LaTeX both fine.

Response

{
  "success": true,
  "api_version": "v1",
  "status": "DISPUTED",
  "verified": false,
  "means": "The answer contradicts the question. Do not show it to a student as correct.",
  "checks_run": 1,
  "checks_passed": 0,
  "checks_failed": 1,
  "checks": [
    {
      "kind": "subst",
      "ok": false,
      "text": "(x,y) = (5,3) in x^2+y^2+1=3xy gives 35 ≠ 45"
    }
  ]
}
FieldNotes
verifiedBoolean. true only for CHECKED. This is the field to branch on.
checks[].kindsubst disputes the answer; arith disputes a step in the working.
checks[].textHuman-readable and safe to show a student verbatim.
checks orderFailures first. A receipt that buries the failure under ten ticks contradicts its own heading.

What it can check

Substituting claimed roots and tuples back into the question’s equation; arithmetic written in the working; exact surd forms such as 82 ± 30√7; fraction equalities. It deliberately declines trigonometric equations, because degrees-or-radians is a convention your question may not share and a wrong verdict is worse than none.

Solve, deterministically

POST /v1/math/solve key required

Solves without asking a model anything, so it cannot hallucinate and costs nothing per call. 

curl https://7solve.7by.in/v1/math/solve \
  -H "Authorization: Bearer $SEVENSOLVE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"equation": "x^2 - 164x + 424 = 0"}'
{
  "success": true,
  "status": "SOLVED",
  "kind": "quadratic",
  "variable": "x",
  "roots": [2.627460668, 161.372539332],
  "exact_form": ["82 + 30√7", "82 - 30√7"],
  "discriminant": 25200,
  "method": "exact (quadratic formula)",
  "complete": true
}
StatusMeans
SOLVEDRoots found. Check complete.
IDENTITYTrue for every value of the variable.
NO_SOLUTIONReduces to a false statement.
NO_SOLUTION_FOUNDNothing found in the searched range. Not the same as “none exist”.
UNDEFINEDDivision by zero, or a root of a negative.
UNSUPPORTEDOutside what it can prove it handles. reason says why.

complete: false means the root list may be partial. Linear and quadratic equations are solved exactly and are always complete. Anything else falls to numeric bisection over −1000 to 1000, which misses roots outside that range and repeated roots that never cross zero. The response says so in note rather than leaving you to find out.

It refuses more than one variable, trigonometric equations, and anything the parser declines. A solver that guesses is indistinguishable from one that knows, so this one does not guess.

Solve with a model, then verify

POST /v1/solve key required

Routes the question to a language model, verifies the reply, and — if the verdict is DISPUTED — discards it and tries the next engine. You get the first answer that survives checking, not the first answer produced. 

curl https://7solve.7by.in/v1/solve \
  -H "Authorization: Bearer $SEVENSOLVE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "question": "Solve x^2 + 4x + 6 = 0",
    "class": "10",
    "subject": "mathematics",
    "language": "English",
    "explanation_level": "class_10"
  }'
FieldNotes
questionRequired. Up to 8000 characters.
class, subject, language, explanation_levelOptional. They shape how the answer is written.

The response carries answer, the same verification block as /verify, the engine that produced it, and an attempts array showing every engine tried with its latency and outcome. If every engine returned a disputed answer, status is UNCERTAIN and the best available reply is returned clearly labelled — never silently.

Unlike the two endpoints above, this one calls a model, so it is the one with a real per-call cost and a dependency on upstream availability.

Health

GET /v1/health no key

Safe to poll from a monitor. The engine field reflects a live self-check of the verifier, not just “the process is up”.

{
  "success": true,
  "status": "HEALTHY",
  "engine": "ok",
  "detail": null,
  "store": "writable",
  "time": "2026-08-18T03:55:00+00:00"
}

status is HEALTHY, DEGRADED, or DOWN. A degraded engine returns 200 with a detail string; a down one returns 503.

Managing keys

Key administration uses your admin token, not a customer key.

# issue
curl -X POST https://7solve.7by.in/v1/keys \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"label": "acme-edtech", "rate_per_hour": 600}'

# list (prefixes only — never the key itself)
curl https://7solve.7by.in/v1/keys -H "Authorization: Bearer $ADMIN_TOKEN"

# revoke
curl -X DELETE https://7solve.7by.in/v1/keys/k_9f3c1a2b \
  -H "Authorization: Bearer $ADMIN_TOKEN"

Revoking marks a key dead but keeps its history, so a key id in an old log can still be explained.

Usage

GET /v1/usage key required

Returns this key’s own counters — the current hour against its limit, and totals per day broken down by route.

Limits

LimitValueOn exceeding
Requests per hour, per key600 by default429 with Retry-After
Request body256 KB413
/solve question8,000 chars413
/math/solve input2,000 chars413

Every authenticated response carries X-RateLimit-Limit and X-RateLimit-Remaining. The window is fixed and resets on the hour.

Errors

Every failure has the same shape, including the ones thrown by the framework itself.

{
  "success": false,
  "api_version": "v1",
  "status": "RATE_LIMITED",
  "message": "This key has used its 600 requests for this hour."
}
StatusHTTPMeans
UNAUTHORIZED401Missing, unrecognised, or revoked key.
NEEDS_CLARIFICATION400A required field is missing or empty.
RATE_LIMITED429Hourly limit reached. Honour Retry-After.
FAILED4xx / 5xxEverything else. message says what went wrong.

Unknown routes return 401 rather than 404 when unauthenticated — route names are not revealed to callers without a key.
